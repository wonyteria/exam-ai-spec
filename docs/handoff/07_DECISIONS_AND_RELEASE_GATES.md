# 확정 결정·설계 제안·배포 전 결정

## 1. 사용자 확정 사항

| ID | 확정 내용 | 제품 영향 |
|---|---|---|
| D-01 | 여러 학원이 사용하는 서비스 | tenant/권한/문서·브랜드·작업 격리 필수 |
| D-02 | 학원은 웹만 사용 | 학원 PC에 Codex·한글·worker 설치 흐름 없음 |
| D-03 | 플랫폼이 AI와 한글 변환 제공 | 중앙 추론·Windows 변환·운영비/큐/복구 관리 |
| D-04 | Codex 구독은 개발·검증에 활용 | 개인 계정으로 공용 서비스 추론을 제공하지 않음 |
| D-05 | 개발은 Devin에게 인계 | 이번 산출물은 명세/계획/테스트이며 제품 구현이 아님 |
| D-06 | 원문 번호·지문·보기 보존, 학생 필기 제외, 도형 재작도, 논술 공간 보존 | 원문 coverage/인쇄 보존/필기 제외/도형 검증을 따로 실시 |
| D-07 | 숫자 it·단위 roman·실제 수식 11pt·열당 2문항·행 정렬 | 실제 객체·레이아웃 검사 필수 |
| D-08 | 문제마다 정답+학년 수준의 풀이를 미주에 삽입, 최종 오탈자/수식 검수 | 모든 채점 단위와 실제 미주 coverage, 교과/풀이 검증 |

기존 개인 PC용 CodexCliProvider 제안은 개발/QA 방식의 후보로만 남는다. 학원마다 Codex와 Windows PC를 연결하는 구조는 D-02/D-03에 따라 V1 운영안에서 제외했다. 이전 Gemini 재시도는 현재 기본 계획에 없다.

## 2. 채택할 설계 제안과 대안

| ADR | 제안 | 대안과 선택 이유 | 검증/후속 |
|---|---|---|---|
| ADR-01 | 기존 Next/FastAPI를 유지하고 도메인 계약을 강화 | 전면 재작성은 기존 경로/테스트를 잃고 범위가 커짐 | baseline 이후 작은 PR로 교체 |
| ADR-02 | PostgreSQL 트랜잭션 + private object storage + lease 기반 durable queue | 현재 JSON/daemon은 다학원 동시성·복구에 부족. 초기부터 복잡한 분산 메시지 스택을 사용하면 운영 부담 발생 | 추가 의존성 승인, schema/migration/queue 부하 시험 |
| ADR-03 | 운영 OpenAI API, Luna/Terra 품질·비용 비교 | 개인 Codex 계정을 통한 공용 운영은 사용자 확정 사항과 불일치. Gemini 기본 운영 제외 | 계정/최신 모델/단가·평가 결과로 선택 |
| ADR-04 | 중앙 Windows worker에서 실제 한글 변환/proof | 학원 PC 설치는 D-02와 불일치. 파일 확장자만 바꾸는 HWP는 불가 | 사용 조건·설치·actual roundtrip gate |
| ADR-05 | canonical revision + 별도 content/style/proof/artifact | API별 중복 필드 수정/고정 파일 덮어쓰기는 stale 자료 문제를 반복 | CAS·invalidation·undo·hash 시험 |
| ADR-06 | RESTORE source fidelity와 EDIT intended changes 분리 | 원문 비교를 무조건 적용하면 의도된 편집은 영원히 실패. 원문을 수정하면 추적 불가 | 변경 경계별 증거/비교 기준 |
| ADR-07 | 포맷별 final eligibility | HWP 불가를 0으로 통과시키거나 모든 파일을 무조건 막는 전역 flag는 부정확 | 해당 파일의 proof로만 다운로드 |
| ADR-08 | MAJOR_GROUPED 미주, 기본 STUDENT_WITH_ENDNOTES | 샘플의 대문항 23개 미주에 답안 28개의 풀이를 수록. 대안 LEAF는 템플릿 정책으로만 적용 | 답안 coverage 100%, 학생 전용 모드에서 답안 비노출 |
| ADR-09 | A4 기본, 2열×각 열 2문항, 열 우선 순서, 행 높이 맞춤 | 참고 HWP는 B4이고 서식 오류가 있음. 페이지 수/픽셀을 그대로 복사하지 않음 | 긴 문항/논술형 예외와 실물 레이아웃 검사 |

위 설계는 Devin이 구현하면서 검증할 제안이다. 의미/출고 품질/보안을 약화하는 변경은 근거와 대안, 영향 테스트를 기록하고 제품 책임자의 결정을 받는다. 사소한 내부 함수명/파일 분할은 요구사항을 지키는 범위에서 개발자가 결정한다.

## 3. 배포 전 결정해야 할 항목

| Gate | 결정·증거 | 책임 | 언제 필요한가 | 미완료 시 가능한 작업 |
|---|---|---|---|---|
| RG-01 | 호스팅/지역/도메인/TLS/운영 접근자 | 제품·운영 책임자 | stage/public 배포 전 | 로컬/CI와 인프라 설계 |
| RG-02 | 인증 서비스·초대 정책·admin/지원 접근 | 제품·보안 책임자 | 다학원 stage 전 | auth interface/mock, 권한 테스트 |
| RG-03 | 운영 OpenAI 계정/secret/모델 접근·단가·월간/학원 예산 | 운영·제품 책임자 | 유료 평가/운영 추론 전 | mock/cache-only tests, adapter 구현 |
| RG-04 | 원본/학생 정보의 외부 처리 승인·고지·보관/삭제 정책 | 학원 계약·개인정보 책임자 | 실제 학생 자료 전송 전 | 합성 자료와 승인된 fixture 평가 |
| RG-05 | 중앙 한글 설치·서버 자동화 사용 조건/라이선스·폰트 | 운영 책임자 | actual HWP test/public HWP 전 | schema/HWPX 렌더러/COM 대역 테스트 |
| RG-06 | 지원 수식/도형/표/그래프·학년/진도 카탈로그 | 제품·수학 검수 책임자 | 모델/renderer 평가 고정 전 | 미지원 항목의 차단·issue 경로 |
| RG-07 | 평가 corpus 사용권·라벨·검토·holdout 분리 | QA·수학 검수 책임자 | 정확도 주장/파일럿 승인 전 | 기존 샘플·공격 fixture 회귀 |
| RG-08 | 파일/페이지/동시 작업·cost cap·SLO·보관 기간 | 운영·제품 책임자 | 파일럿 전 | 설정 가능한 제한·관측 구현 |
| RG-09 | backup 주기/복구 목표·삭제/백업 만료·지원 runbook | 운영 책임자 | 실제 학원 데이터 운영 전 | backup/restore 자동화·검증 |
| RG-10 | 출시 QA 수치·최종 검토자·파일럿 학원/기간 | 제품·QA 책임자 | Pilot/공개 출시 전 | 테스트 자동화·제안 목표 측정 |

이 항목은 지금 사용자를 다시 인터뷰해야만 모든 개발을 시작할 수 있다는 뜻이 아니다. Devin은 책임자·기한·현재 상태를 기록하고, 막히지 않는 코드/계약/테스트를 진행한다. 외부 서비스 가입·결제, 계정 권한 확대, 원본 자료 전송, 공개 배포는 실제 승인 범위 안에서만 수행한다.

## 4. 출시 gate와 증거 수준

| 단계 | 필요한 증거 | 표시할 수 있는 상태 |
|---|---|---|
| 개발 계약/모의 테스트 완료 | schema/API/단위·통합/오프라인 회귀 | 개발 기능 구현. 실제 추론/한글 미검증 항목은 별도 표시 |
| 내부 Alpha | 심원중 원본+오류 fixture의 전체 여정, 실제 객체·한글 열기 | 해당 샘플에서 확인. 일반 정확도는 미확정 |
| 제한 Pilot | 승인 자료·복수 학원/역할·동시성·지정 QA 출고 검토·비용/복구 관측 | 제한 운영. known limits 명시 |
| V1 공개 출시 | 독립 holdout·실제 한글 3형식·보안·backup restore·운영 정책·critical 0 | 명시한 지원 범위에서 출시 가능 |

04 문서의 holdout 시험 30개/채점 단위 1000개와 원문 99.5%·도형 98%·풀이 95%는 초기 자동 처리 품질의 **설계 제안값**이다. 최종 파일에 이 비율만큼 오류를 허용한다는 뜻이 아니다. 실제 final에서 관측된 critical 오류는 0이어야 하고, 불확실한 경우에는 검토/차단이 동작해야 한다. 평가 크기와 목표는 RG-07/RG-10에서 실측·비용·대표성을 보고 고정한다.

오류가 0개 관측되었다고 해서 모든 미래 입력의 무오류를 증명한 것은 아니다. 지원 범위와 샘플 분포, 검토 개입, 거절률, 미검증 항목을 함께 보고한다.

## 5. 주요 실패 시나리오와 대응

| 실패 | 피해 | 예방·검출·복구 |
|---|---|---|
| AI가 학생 필기/잘못된 그림을 인쇄 조건으로 채택 | 잘못된 시험지와 정답 | original-clean-variant 출처, 인쇄 보존/필기 제외 검사, 그림 관계/원문 대조, field issue |
| 저비용 모델이 틀린 답을 일관되게 반복 | 거짓 합의/final 오류 | 독립 데이터/검증 경로, 답 기호 대조, 실제 holdout, cache provenance |
| 학원 A/B의 작업 파일 또는 URL이 섞임 | 학생 자료 유출·오출력 | 모든 경로의 tenant/ACL, job temp 격리, hash manifest, 부정 테스트·audit |
| 한글 worker 정지/실패를 성공으로 처리 | 파일 없음/오래된 파일/거짓 proof | lease/fencing, timeout, Open/SaveAs 검사, actual file hash, 포맷별 blocker |
| 수정 중 이전 worker가 완료 | 최신 문서 덮어쓰기/이전 정답 출고 | CAS/input revision/fencing, immutable artifact, stale 결과 차단 |
| 예산·rate limit 소진 | 전체 학원 작업 정지·비용 폭증 | budget reservation, tenant fair queue, backoff, WAITING_QUOTA, 자동 유료 fallback 금지 |
| 백업 복구/삭제 정책 불일치 | 데이터 손실·지운 원본 재노출 | 복구 훈련, 삭제 tombstone 재적용, 만료 정책, 지원 권한 감사 |

## 6. 명세 변경 규칙

사용자 확정 > 최신 이 패키지의 상호 일치한 계약 > 당시 코드 감사 > 오래된 스펙/주석/예시 순으로 해석한다. 명세 내부에 충돌이 있으면 임의로 편한 쪽을 선택하지 않고, 관련 요구사항/테스트/버전을 함께 수정해 기록한다. 새 모델/템플릿/renderer/한글 버전/폰트/검증기 변경 시 해당 평가와 proof를 다시 검증한다.
