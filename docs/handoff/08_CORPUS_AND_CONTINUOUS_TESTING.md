# 실제 자료 수집과 지속 테스트 개발

기존 REQ-27, WP00·WP11, AT-019~048·058~060, F0~F4를 구체화한다. 이 문서는 자동 테스트를 예약하거나 Devin 작업을 실행한 기록이 아니다.

## 1. 역할 분리

- **자료 큐레이터:** 출처 탐색, 실제 표본 확인, 원본·필기·채점·정답 연결, 사용 범위·개인정보·중복 검수, 기준 데이터 작성과 검토 요청.
- **Devin 개발:** 공개된 개발·회귀 세트로 실패를 재현하고 구현·테스트를 수정한다. 비공개 최종 평가의 정답에 접근하지 않는다.
- **독립 QA·수학 검수자:** 원문·정답·해설·도형·서식 기준을 확정하고, 잠긴 평가 세트를 별도 환경에서 실행·판정한다.
- 같은 모델이 만든 출력과 같은 모델의 “맞다” 판정만으로 정답 기준(ground truth)을 만들지 않는다. AI 초안에는 독립 확인이 필요하다.

## 2. 수집 상태를 정확히 표시

`DISCOVERED → SOURCE_CHECKED → ACCESS_PENDING/RIGHTS_PENDING → DOWNLOADED_QUARANTINE → PRIVACY_REVIEWED → CONTENT_REVIEWED → APPROVED_REGRESSION/LOCKED_EVALUATION`.

라이선스와 데이터 적합성은 별개다. 사용이 허용돼도 학생 답안지만 있고 인쇄 문제는 없으면 한국 수학 시험지 전체 복원의 정답 기준(gold)으로 쓸 수 없다. 출처의 CC 표기와 코드 저장소 라이선스, 교재 원문의 권리, 제3자 개발자·외부 AI에 대한 제공 범위를 구분한다. 공개 이미지를 곧 재배포 허용 자료로 간주하지 않는다.

AI-Hub 479·71716은 한국어 수학 후보지만 실제 전송·평가 목적과 다운로드·제3자 제공·국외 처리 조건을 확인해야 한다. DrawEduMath 등 NC 자료와 권리 표기가 충돌하는 자료는 승인 전 자동 수집·개발 패키지 편입에서 제외한다. 새롭게 확보된 공개 표본은 별도 출처 매니페스트(source manifest)로 관리한다.

## 3. 세트 구성과 수량

- 첫 수집·검수 묶음은 **핵심 한국 수학 실제 시험 10종**을 목표로 한다. 이는 아직 확보한 수량이 아니다. 학년·학기, 대수·기하, 논술, 흐림·필기 겹침이 다양하게 포함되도록 구성한다.
- 첫 10종의 일부는 개발·회귀에 쓰고, 일부는 큐레이터가 잠가 처음 보는 입력에 대한 예비 평가에 쓴다. 작은 예비 평가의 결과를 정식 출시 조건 충족으로 보고하지 않는다.
- 정식 출시 평가는 기존 제안대로 **독립 시험 30종 이상이면서 총 1,000개 채점 단위 이상**이다. 개발용으로 사용한 시험은 제외한다. 30종으로 1,000개 단위가 안 되면 두 조건을 모두 충족할 때까지 확보한다.
- 해외 답안, 손글씨 수식 조각, 복제·크롭·회전본, 같은 시험에 대한 학생 50명의 답안은 각각 보조 자료군으로 집계한다. 이미지 1,000장이 독립 시험 1,000개라는 뜻은 아니다.
- 공개 인터넷 자료는 모델의 사전 학습에 이미 포함됐을 수 있다. “Devin에게 미공개”와 “기반 모델이 처음 봄”을 구분하고, 승인된 비공개 현장 자료로 보완한다.

## 4. 데이터 분할과 정답 유출 방지

분할 단위는 파일이 아니라 학교·연도·시험·문항의 출처 그룹(family)이다. 같은 문제의 빈 원본·여러 학생의 필기·정답·해설·크롭·회전본은 같은 그룹으로 묶는다. SHA뿐 아니라 페이지·문항 유사도와 사람의 검토로 중복을 확인한다.

개발 세트는 Devin이 원문과 정답을 봐도 된다. 최종 평가 세트는 별도 QA 계정·저장소에 두고, 정답·참고 HWP·expected JSON을 개발 작업 공간, 검색 색인, 모델 캐시에 넣지 않는다. “보지 말라”는 프롬프트만으로 보호하지 말고 접근 권한을 분리한다.

잠금 평가 세트를 한 번 열어 실패 사례를 바탕으로 수정했다면, 그 세트는 이후 회귀 자료다. 다음 출시 평가에는 새로운 잠금 분할을 사용하거나 사전에 정한 평가 회차·피드백 제한 정책을 따른다. 같은 평가 세트를 무제한 반복하여 성공할 때까지 맞추지 않는다.

## 5. 샘플별 기준 파일

각 샘플은 다음 항목을 갖는다.

- `sample_id`, `source_id`, 원출처 URL·버전·저작자·라이선스·허용 범위, 수집일, 원본 SHA256.
- 실제·합성·학생 응답·교사 필기·채점·빈 원본의 구분, 언어·학년·과목·시험·문항 출처 그룹, 사용 범위.
- 원본 페이지 순서와 변환 행렬, 본문·수식·선택지·보기 상자·배점·문항 계층·도형 관계·답안 영역의 기준.
- `printed_must_preserve`, `handwriting_must_remove`, `ambiguous_do_not_guess`의 영역과 판정 근거.
- 학생의 답·교사의 표식과 별도로 검산한 정답·풀이·학년 적합성, 허용된 동등 표현과 정규화 규칙.
- 기대하는 한글 수식·도형·미주·폰트·페이지 및 행 정렬·출력 용도와 파일 검증(proof) 규칙.
- 검토자·검토일·불일치 및 해소 상태, 분할 ID, 평가 노출 이력. 미확정 항목이 있으면 정답 기준 확정(golden) 상태로 승격하지 않는다.

학생이 맞게 풀었더라도 그 필기는 삭제 대상이다. 학생이 틀렸거나 교사 채점이 잘못됐을 수 있으므로 필기나 체크를 정답표로 바꾸지 않는다.

## 6. Devin의 반복 개발 규칙

1. 변경 전 버전·데이터 버전·model/prompt/schema/renderer를 고정한다.
2. 승인된 개발 표본에서 오류를 수집하고 원인별로 분류한다: 인쇄 손실·필기 잔존·문항 누락·조건 변형·도형 관계·답과 풀이·학년·한글 객체·미주·배치·권한·복구.
3. 대표 원인마다 가장 작은 실패 회귀 사례를 만든 뒤 원인을 수정한다. 한 샘플에 대한 하드코딩·검증 생략·정답 오염으로 성공시키지 않는다.
4. 수정 영향 범위의 단위·통합·대표 실물 회귀 테스트를 실행한다. UI 문구를 변경할 때마다 모든 시험을 유료 AI로 다시 처리하지 않는다.
5. 의미·모델·전처리·renderer가 바뀌면 관련 자료군 전체와 실제 한글 파일 검증(proof)을 다시 수행한다. 통과한 일부 결과만 골라 보고하지 않는다.
6. 고정된 출시 후보(release candidate)를 독립 QA가 잠금 세트에서 평가한다. 발견한 오류·review/reject 비율·비용·시간·교사 작업량을 함께 보고한다.
7. 미해결 중대(critical) 오류가 있으면 최종 출고를 막고 개발 회귀로 전환한다. 필요한 새 평가 자료를 확보한 뒤 재평가한다.

외부 AI 호출은 승인된 자료·예산·권리 범위에서만 한다. 반복 횟수를 무제한으로 두는 대신 작업(job)·평가 실행(run)별로 호출 수·토큰·비용·시간 한도를 두고, 한도에 도달하면 원인을 기록해 대기한다. mock/replay로 검증할 수 있는 부분은 먼저 처리한다.

## 7. 제출할 반복 테스트 결과

매 평가 실행에 `commit + benchmark_version + split_hash + provider_config + renderer/worker_version`을 기록한다. 결과는 PASS/FAIL/REVIEW/REJECT/NOT_RUN으로 구분하고, 원본·자동 결과·사람이 수정한 뒤의 결과도 구분한다.

숫자·부정어·각과 변의 라벨·도형 관계·정답 오류를 단순 문자 평균으로 숨기지 않는다. 자동 통과한 파일의 중대(critical) 오류와 정상 입력을 과도하게 막는 비율을 둘 다 측정한다. 한국 수학 핵심·해외 보조·부분 문항·합성·negative 자료의 분모를 섞지 않는다.

최종 완료 조건은 기존 04/07을 따른다. 시험지를 많이 돌렸다는 횟수나 한 세트에서 100%가 나왔다는 사실로 모든 미래 입력에 오류가 없다고 선언하지 않는다.

## 8. 현재 확보 현황의 위치

이 패키지의 [공개 후보 목록](./evidence/CORPUS_SOURCE_REGISTRY.json)은 조사·접근 상태를 기록한다. 실제 내려받은 외부 보조 샘플은 사용자에게 별도 corpus ZIP으로 제공하고 개발 명세 ZIP에는 넣지 않는다. 이를 한국어 핵심 시험지 전체 페이지 자료가 확보됐다는 의미로 읽으면 안 된다.

AI-Hub 이용 조건은 [공식 정책](https://www.aihub.or.kr/intrcn/guid/usagepolicy.do?currMenu=151&topMenu=105)에서, 해외 공개 자료는 각 공식 데이터 카드·원소유자의 조건에서 확인한다. 정책 변경과 개별 조건을 확인한 뒤 샘플 상태를 승격한다.
