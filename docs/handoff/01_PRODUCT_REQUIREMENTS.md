# 제품 요구사항 — 여러 학원이 웹으로 사용하는 시험지 복원·한글 제작 서비스

버전 1.0 / 작성일 2026-09-19 / 코드 기준 `0c1fb5dc8223d52889ca676bed13ad2e7d93fa4a`

## 1. 제품 목표와 확정 범위

학원 선생님이 학생이 풀고 채점한 학교 시험지 사진/PDF를 올리면, 인쇄된 문제를 정확히 구조화하고 도형·수식·서술 공간을 재현한다. 필요한 예외만 확인한 뒤 수정과 브랜드 적용을 거쳐 **편집 가능한 HWP/HWPX와 검증된 PDF**를 내려받는다. 모든 문제의 정답과 해당 학년 수준의 풀이를 미주에 포함한다.

사용자가 이번 대화에서 확정한 운영 조건:

- 여러 학원이 각각 사용하는 웹 서비스다.
- 학원은 브라우저만 사용한다. 학원 PC에 Codex·한글·worker 설치를 요구하지 않는다.
- 플랫폼이 중앙 서버의 AI 처리와 Windows 한글 변환을 제공한다.
- Codex 구독은 개발·검증 도구로 활용한다. 운영 추론을 개인 구독 자격 증명 하나로 처리하지 않는다.
- Gemini는 기본 운영 구성에서 제외한다. 운영 AI는 OpenAI API adapter를 기본안으로 두며, 비용·계정 접근·품질은 출시 전에 측정한다. 이번 문서 작성은 API 가입/결제/실행을 승인하거나 수행한 것이 아니다.
- 개발은 Devin이 맡는다. 이 패키지는 구현 계약이며, 현재 구현이 완료되었다는 보고서가 아니다.

### 첫 완성 버전 V1에 포함

학원/사용자/역할, 문서 보관함, 안전한 업로드와 순서 복원, 인쇄 내용 복원, 원본 대조, 수학 논리·풀이 검증, 예외 검토, 기존 문항의 자연어 편집, 버전/되돌리기, 간단한 학원 브랜드/템플릿, 한글 수식·도형·미주·레이아웃, 포맷별 검증/다운로드, 작업 복구, 사용량/비용 제한, 운영·백업·지원.

### V1 이후로 분리

유사 문제 대량 생성, 독립 문제은행/검색·판매, 결제/구독 상품 운영, 다른 교과, 고등수학 전체 범위, 공동 실시간 편집, 외부 학원 간 문서 공유. 이 항목들은 ROADMAP의 확장 기능이며, V1 화면에 작동하는 버튼이나 예시로 노출하지 않는다. 운영자가 초기 학원을 초대하고 한도를 배정하는 방식으로 V1을 운영할 수 있다.

## 2. 품질의 의미와 출시 기준

“완벽”의 실무 정의는 **지원 범위 안에서 정확한 결과를 검증하고, 정확성을 확인하지 못한 결과를 최종본으로 오인시키지 않는 것**이다. 임의의 흐린 사진까지 무조건 오류 없이 복원한다고 약속하지 않는다.

다음 조건을 모두 지킨다.

1. 기준 원문과 대조해 확인하지 않은 문구/숫자/보기/배점/필수 도형 객체가 최종본에 남지 않는다.
2. 학생 필기·정답 체크를 인쇄 문제·정답으로 승격하지 않는다. 인쇄선을 훼손한 전처리 결과를 근거 없이 확정하지 않는다.
3. 정답, 계산값, 선택지 내용, 정답 기호와 해설의 결론이 일치한다.
4. 수식/도형/미주가 실제 한글 객체로 존재하며, 합의한 서식·답안 공간을 충족한다.
5. 검토 확정이나 AI 편집 후에는 실제 문서와 미리보기·검증·출력이 같은 revision을 사용한다.
6. 필수 검증이 NOT_RUN/UNAVAILABLE/FAILED이면 해당 포맷의 최종 출고를 막는다. 생략은 성공이 아니다.
7. 다른 학원의 자료·작업·브랜드·사용량은 어떤 경로에서도 읽거나 변경할 수 없다.
8. 독립 평가 세트와 실제 Windows 한글 검증을 통과한 증거를 바탕으로 출시한다. 테스트 개수나 캐시 재생만으로 출시하지 않는다.

교사의 검수량을 줄이는 것은 최적화 목표다. 필요한 예외 검토를 감추거나 잘못된 자동 확정으로 검수량을 줄여서는 안 된다. 자동 통과율·교사 작업 시간·재시도·부당 차단율은 별도로 측정한다.

## 3. 원문과 참고자료의 우선순위

1. 사용자 원본 사진/PDF의 **인쇄 내용**이 복원 기준이다.
2. 사용자의 이번 요구(숫자 it / 단위 roman / 11pt / 열당 2문항 / 모든 풀이를 미주에 삽입)가 서식 기준이다.
3. 독립 수학 검산이 정답·풀이 기준이다.
4. 사람이 작성한 HWP는 제작 방식의 참고본이다. 그 파일의 누락/오탈자를 따라 하지 않는다.

원문 자체에 오류가 있으면 원문은 보존하고 별도 이슈로 기록한다. 교사가 의도적으로 수정한 문서는 RESTORE 출처에서 EDIT 출처로 변경된 이력을 갖는다. 수정값이 원문과 다르다는 이유로 의도된 편집을 복원 오류로 처리하지 않되, 새 조건의 정답·풀이·도형·출력은 다시 검증한다.

## 4. 지원 입력과 경계

JPG/JPEG/PNG 및 페이지가 있는 PDF를 V1 기본 입력으로 한다. 현재 UI에 있는 BMP/WebP는 decode·EXIF·출력 회귀 검사를 통과할 때만 capability로 켠다. 지원하지 않는 HEIC, 암호화 PDF, 비정상/손상 파일은 업로드 시 분명한 메시지로 거절한다. PDF 안의 script/첨부/외부 resource를 실행하지 않는다.

초기 설정 제안: 파일당 50MiB, 문서당 50페이지/총 200MiB, decode 후 이미지당 40MP, 외부 AI 재시도는 요청당 최대 2회이며 백오프를 적용한다. 서버 환경의 부하 시험 후 이 값을 조정한다. 환경 설정/문서/UI의 값은 같은 capability 응답을 사용한다. 이 값은 측정된 처리 능력이나 사용자가 확정한 예산이 아니다.

전체 시험지뿐 아니라 일부 페이지 입력도 허용한다. 메타데이터에서 전체/일부 모드를 명시하고, 일부 페이지만 입력했다는 이유로 1번부터 모든 번호를 강제하지 않는다. 예상 coverage를 확정하지 못하면 그 범위를 최종 검증에서 분명히 표시한다. 문서가 전체 시험지라고 선언된 경우 페이지/문항 누락을 무시해서는 안 된다.

## 5. 사용자 역할과 접근

Owner는 학원의 구성원·브랜드·한도·보관 정책을 관리한다. Admin은 위임된 학원 관리를 한다. Teacher는 본인 문서와 공유받은 문서를 생성·편집·출력한다. Reviewer는 배정된 문서의 검토 항목을 처리하며, 학원 전체 설정이나 임의 문항 저작 권한은 없다. 플랫폼 운영자는 시스템 상태를 관리하지만, 모든 학생 원본의 열람 권한을 기본으로 받지 않는다.

역할명만으로 UI를 숨기는 방식은 허용하지 않는다. tenant membership + resource grant + action permission을 서버에서 평가한다. 학원 전환 시 열린 문서/요청/캐시 상태를 새 학원으로 잘못 이어 붙이지 않는다. 역할별 상세 표는 02·03 문서를 따른다.

## 6. 요구사항과 완료 판정

아래 요구사항은 모두 V1 출시 범위다. 자세한 API/상태 계약은 02, 화면/팝업은 03, 테스트는 04 문서로 연결된다. 감사 근거의 경로는 저장소 기준 상대 경로이며, 해당 HEAD의 위치다.

### REQ-01 — 학원 격리·로그인·역할 권한

- 초대/로그인/학원 선택/가입 해제/역할 변경을 지원한다. 인증 provider는 WP00에서 선택하되, 자체 비밀번호 보관을 임의로 구현하지 않는다.
- document/job/asset/crop/export/proof/history/SSE 모두 tenant와 권한을 검증한다. 사용자가 입력한 tenant_id를 권한의 근거로 신뢰하지 않는다.
- 다른 학원 ID를 넣은 조회/쓰기/다운로드와 권한 회수 후 요청이 거절되고, 내용·존재 여부가 불필요하게 노출되지 않는다.
- 현재 근거: `backend/app/main.py:9`, `backend/app/api/documents.py:27`, `backend/app/api/jobs.py:19`의 인증 없는 API. A13/보안 설계 갭.

### REQ-02 — 문서 보관함·검색·재개·보관/삭제

- 문서 이름, 학교/학년/시험, 상태, 수정자/시간, 현재 revision, 검토 대기 수, 포맷별 산출물 상태를 보여준다.
- 페이지네이션/필터/검색, 중단 작업 재개, 문서 복제, 보관/복원과 삭제를 지원한다. 복제 문서는 새 ID·원본 출처·권한을 가지며, final 증거를 무조건 복제하지 않는다.
- 새로고침하거나 직접 URL로 들어와도 본인 문서를 찾고 이전 작업을 이어간다. soft-delete 자료는 검색·다운로드에서 빠진다.
- 현재 근거: 현재 5개 `frontend/app/**/page.tsx`에는 library 경로가 없음; F16 및 03 라우트 목록.

### REQ-03 — 안전한 업로드·manifest

- 원본은 해시와 불변 assetId로 저장하고, 표시용 파일명은 별도로 보존한다. 동일한 이름의 파일 5개도 각각 보존되어 5개 파일로 남는다.
- 타입/크기/페이지/픽셀/압축 폭탄 검사, 안전한 저장 경로, 해시 검증, 중복 요청 idempotency, 실패 파일 재시도를 제공한다.
- 파일 확장자나 사용자가 입력한 filename을 실행/저장 경로로 신뢰하지 않는다. 원본은 전처리/편집 시 덮어쓰지 않는다.
- 현재 근거: `backend/app/api/uploads.py:17,29–31`; A13·A14·A15·A31·A32.

### REQ-04 — 페이지 순서·메타데이터·교과 범위

- 입력 순서와 논리적 시험지 순서를 분리한다. 자동 추정의 근거와 확신이 없는 구간을 확인 UI에서 제시하고, 수동 재정렬을 허용한다.
- 학교·연도·학년·학기·시험 종류·과목·교육과정/진도 profile을 추출/확인한다. 모르는 값은 추측해 확정하지 않는다.
- 사진별 페이지 순서와 원본 anchors가 유지되고, 변경 시 downstream 문항 표시/coverage가 새 revision으로 갱신된다.
- 현재 근거: `preprocessing.py:15`, `document/models.py:171`; A14/S07·S11.

### REQ-05 — 비파괴 전처리·필기 제외·인쇄 보존

- original/normalized/mask/clean/recognition-input을 구분하고, 회전·원근/크롭 변환 행렬을 보존한다.
- 인쇄 보존과 학생 필기 제거를 별도로 검사한다. 원본과 clean을 함께 대조하고, 겹친 획은 출처 없이 임의로 재생성하지 않는다.

- 현재 근거: `student_trace/separator.py:22–61`, `print_layer/engine.py:6–15`; 실제 clean 이미지 S01.

### REQ-06 — 구조화·후보·출처

### REQ-07 — 문항 식별·계층·배점

- 내부 questionId는 불변이다. printedLabel, displayOrder, parentId, scoredLeaf 여부, groupTotal/leafPoints를 구분한다.
- 논술 부모 지문/도형을 자식이 참조한다. 문항 번호·소문항 번호는 원본 그대로 표시하고, 편집 대상은 안정적인 ID로 선택한다.
- 삭제/추가/순서 변경이 중복 번호·배점 이중 합산·부모 없는 자식을 만들지 않는다. 추가 문항은 명시적인 AUTHOR 편집으로만 처리한다.
- 현재 근거: `document/models.py:138–155`, `editing.py:72–76`, `consensus.py:91`; A03/S03.

### REQ-08 — 원본 도형·표·그래프 재현

- 도형의 점/변/교점/라벨/길이/각/등길이/평행/수직/선 종류/채움의 의미를 표현하고, 원문의 관계를 검증한 뒤 재작도한다.
- 표의 셀/병합/머리말과 간단한 좌표 그래프의 축/눈금/원점/점/선/라벨을 보존한다. 지원이 검증되지 않은 복잡한 그래프는 capability로 제한한다.
- 모델이 자유롭게 생성한 SVG/script를 실행하지 않는다. 허용된 scene primitives를 프로그램이 렌더한다. 최종본은 native/vector 객체로 재현하며, crop만 넣은 것은 재작도 합격으로 인정하지 않는다.
- 현재 근거: `document/models.py:98`, `hwpx/renderer.py:54–70`; A08/S04·S05.

### REQ-09 — 편집 가능한 수식·서식

- 본문·보기·도형 라벨·미주에 포함된 수학 숫자/표현은 실제 한글 수식 객체로 생성한다. 숫자 it, 단위 roman, 수식 11pt를 적용한다.
- 수식 AST/토큰·표시 script·의미를 구별하고, 번역할 수 없는 표현은 해당 필드의 이슈로 보낸다. raw LaTeX 평문으로 조용히 대체하지 않는다.
- 수식 크기 11pt±0.1pt, 단위/숫자 스타일과 편집 가능성을 실제 객체/앱 열기/재렌더로 확인한다. 문서 장식 번호는 수학 표현과 분리한다.

## 7. 실물 샘플 합격 기준

심원중 샘플의 정확한 순서는 `_02 → 기본 → _04 → _03 → _01`이다. 대문항 23개/채점 단위 28개/계층 31개/100점, 선택지 100개와 4번 보기 3개를 기준으로 한다. 이 숫자를 모든 시험지에 hardcode하지 않는다.

객관식 독립 정답: `④③③③⑤ / ①①④①⑤ / ②②⑤⑤② / ③②④⑤⑤`.
기존 expected 오류 문항: 2·4·8·9·10·14·20번. 학생의 10번 ④/16번 ②는 오답이다. 기준 정답은 모델 추론 입력에 유출하지 않는다.

필기 제거 검사 영역: 6번 DC/직각, 9번 AC, 12번 AD·BC, 14번 B-F-E, 17번 마름모/수선, 18번 대각선, 4번 보기 상자. 인쇄된 필수 조건인 3번 AE⊥BE의 보존과 객관식 11·15번의 학생 보조 스케치 제외를 확인한다.

참고 HWP에는 수식 232개의 크기가 10pt인 문제, 객관식 해설 부재, 13번 그림 누락, 배점/문구 오타가 있다. 참고 파일의 객체 수인 수식 372개/미주 23개와 똑같이 맞추는 것은 합격 조건이 아니다. 모든 의미 대상의 coverage가 중요하다.

## 8. 설계 제안과 미확정 운영 결정

확정된 것: 다학원 웹 서비스, 중앙 AI/HWP, 개발용 Codex 구독, 이번 변환 요구와 기존 핵심 수정 기능.

배포 전에 확정할 것: 호스팅/지역/도메인, 인증 서비스, 정식 한글 서버 사용 조건/설치, 운영 API 계정·예산, 보관/삭제 기간, 실측 SLO·파일럿 학원 수.
