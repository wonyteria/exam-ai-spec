## 2. 공통 화면 구조와 권한

### 2.1 앱 구조

- 전역 바: 현재 학원 이름·전환, 문서함, 새 시험지, 작업 현황, 내 계정. 관리 권한이 있을 때만 학원 설정을 표시한다.
- 문서 바: 제목, 학교·학년·시험, 현재 버전, 저장 상태, 담당자, 검토 요청 수. 탭은 `원본과 검토 / 편집 / 내보내기 / 변경 이력`이다.
- 상태는 `저장됨`, `변경안 준비 중`, `재검증 필요`, `검증 중`, `검토 필요`, `형식별 출력 준비`를 구분한다. 단순히 초록 `완료` 하나로 합치지 않는다.
- 원본 복원과 사용자 편집의 출처를 나눈다. 원문 복원 중 표현·수치·조건을 몰래 고치지 않는다. 사용자 수정 적용 이후 문서는 `편집본`이며 원본 대비 변경을 열람할 수 있다.
- 일반 사용자 용어는 `원본 대조`, `풀이 확인`, `파일 검사`로 쓴다. `ATU`, `gate dict`, 로컬 절대경로, 내부 예외 스택은 노출하지 않는다. 지원용 오류 코드·추적 번호는 복사 가능하다.
- 문서 탭·선택 문항·검토 필터는 URL에 보존 가능하되, 학생 정보와 자연어 요청 원문은 URL에 넣지 않는다. 서버 권한 판정 후에만 해당 내용을 읽는다.

### 2.2 역할과 문서 접근

아래는 V1 기본값이다. 서버의 인증·인가 계약이 우선하며 버튼 숨기기만으로 접근을 막지 않는다. 동일 계정이 여러 학원에 속해도 학원별 역할·목록·작업·사용량은 분리한다.

| 기능 | owner(소유자) | admin(관리자) | teacher(교사) | reviewer(검토자) |
|---|---|---|---|---|
| 문서 조회 | 학원 전체 | 학원 전체 | 본인/공유 문서 | 배정 문서 |
| 원본 업로드·문서 생성 | 가능 | 가능 | 가능 | 불가 |
| 같은 학원 문서 복제 | 가능 | 가능 | 원본 READ + 학원 CREATE 권한 | 불가 |
| 문서 보관·보관 해제 | 가능 | 가능 | 불가; 관리자에게 요청 | 불가 |
| 원문 판독 검토·풀이 검토 | 가능 | 가능 | 접근 문서 가능 | 배정 문서 가능 |
| 조건·수치·서식 등 사용자 편집 적용 | 가능 | 가능 | 편집 권한 문서 | 불가; 수정 제안은 가능 |
| 검증 재실행 | 가능 | 가능 | 편집 권한 문서 | 배정 문서 가능 |
| 파일 생성·다운로드 | 가능 | 가능 | 출력 권한 문서 | 미리보기만 기본 허용 |
| 공유·담당/검토자 배정 | 가능 | 가능 | 관리자에게 배정 요청 | 불가 |
| 브랜드 기본값·템플릿 관리 | 가능 | 가능 | 선택/문서별 허용 설정 | 불가 |
| 구성원 초대·역할 변경 | 가능 | owner 제외 가능 | 불가 | 불가 |
| 소유권 이전·학원 폐쇄 | 가능 | 불가 | 불가 | 불가 |

교사 간 기본은 본인/명시적 공유 문서다. 공유·접근권 생성/변경/철회는 owner/admin만 수행한다. 학원 관리자는 학원 운영상 전체 접근한다는 사실을 공유 화면에 표시한다. 검토자의 확인은 자신이 검토한 필드·근거에만 적용된다. 문서 편집 권한과 명시적 `EXPORT` 권한을 별도로 검사한다. 교사 본인 문서는 생성 시 정책에 따라 `EXPORT`를 부여하고, 공유 문서는 owner/admin이 해당 권한을 부여했을 때만 최종 파일을 제공한다. reviewer에는 부여하지 않는다. 역할명이 높다고 파일 검사 실패나 치명적 오류를 강제 통과할 수 없다. 검토자가 작성자와 달라야 하는 별도 승인 절차는 V1 기본 요구로 만들지 않는다. 시범 출시의 지정 검토자 서명은 제품 출시 인수 절차이며 매 교사 작업에 강제하는 추가 단계가 아니다.

플랫폼 운영자(`platformoperator`)는 별도 운영 화면·권한이다. 학원 소유자와 동일하지 않다. 서비스 상태·작업 실패·총량을 운영하며, 고객 원본 접근은 명시적 지원 권한과 기록 없이 제공하지 않는다.

### 2.3 공통 조회/변경 상태

| 상태 | 화면 및 허용 동작 |
|---|---|
| 초기 조회 | 제목 자리·스켈레톤 + `문서를 불러오는 중`; 편집/출력 비활성 |
| 정상 빈 목록 | `아직 문서가 없습니다` + 권한에 따라 `새 시험지`; 오류와 구분 |
| 없음 또는 다른 학원 문서 | 존재 여부를 노출하지 않는 `문서를 찾을 수 없거나 접근할 수 없습니다` + 문서함 |
| 같은 학원의 허용되지 않은 동작 | 서버 403과 `이 작업을 수행할 권한이 없습니다`; 관리자에게 권한 요청 안내, 요청을 성공으로 처리하지 않음 |
| 로그인 만료 | 변경 요청 중단·사용자 초안 보존·재로그인 후 권한/버전 재조회; 자동 중복 적용 금지 |
| 네트워크/서버 오류 | 실패 동작·사용자 입력 유지·재시도·문서함; raw HTML/스택 표시 금지 |
| 버전 충돌 | `다른 사용자가 수정했습니다` + 변경안 비교/최신본 다시 열기; 마지막 저장 덮어쓰기 금지 |
| 저장 응답 불명확 | `저장 여부 확인 중`; 요청 ID로 결과 조회 후 재시도 허용; 성공 토스트로 추측 금지 |
| 권한 회수 | 추가 조회·저장·다운로드 중단, 민감한 화면 데이터 제거, 권한 안내 |
| 서버 저장 성공 | 응답 버전·검증 상태 반영 후 `저장됨`; 최신본과 다른 미리보기에는 버전 안내 |

캐시는 학원/사용자/문서/버전을 키로 구분한다. 학원 전환·로그아웃 시 이전 학원 데이터가 순간적으로 보이지 않게 초기화한다. 복수 탭에서 권한/버전 변경을 감지하면 재조회한다.

## 3. 경로와 페이지 역할

`{w}`는 학원 workspace 식별자, `{d}` 문서 ID, `{j}` 작업 ID, `{r}` 버전 ID, `{a}` 파일 ID다. 경로상의 ID는 권한 증명이 아니다.

| 경로 제안 | 목적 / 기존 경로 매핑 |
|---|---|
| `/login`, `/invite/{token}` | 로그인·초대 수락. 로그인 이후 원래 허용 경로 복원 |
| `/workspaces` | 소속 학원 선택·초대 상태 |
| `/w/{w}/documents` | 문서함·필터·재개. 로그인 후 기본 홈 |
| `/w/{w}/documents/new` | 새 원본 준비. 기존 `/` 업로드 기능 이전 |
| `/w/{w}/jobs`, `/w/{w}/jobs/{j}` | 작업 목록·진행. 기존 `/jobs/[id]` 이전 |
| `/w/{w}/documents/{d}/review` | 원본 비교·예외·정답/풀이 검토. 기존 review 이전 |
| `/w/{w}/documents/{d}/editor` | controlled edit·레이아웃·문항 선택. 기존 editor 이전 |
| `/w/{w}/documents/{d}/export` | 용도/형식 선택·생성·파일 상태. 기존 export 이전 |
| `/w/{w}/documents/{d}/history` | 버전 비교·변경안·복원 |
| `/w/{w}/documents/{d}/artifacts/{a}` | 해당 파일의 검사 결과·정확한 버전 미리보기 |
| `/w/{w}/settings`, `/members`, `/brand`, `/usage` (settings 하위) | 학원 정보·구성원·기본 템플릿·사용량 |
| `/account` | 개인 계정·소속·접근 가능한 로그인 관리 |
| `/ops` 하위 | 별도 플랫폼 운영자 상태·처리 큐·HWP 서비스 상태 |

기존 document/job 링크는 로그인·권한 확인 뒤 소속 workspace를 서버에서 결정해 이동한다. `?doc=`는 문서 연결의 원천으로 사용하지 않는다. 링크에 타 학원 ID를 조합해도 데이터가 나오지 않는다. 첫 버전에서 경로 형태를 바꾸더라도 이 기능/권한/복구 계약과 기존 링크 호환은 유지한다.

## 4. 로그인·학원 선택·초대

| 컨트롤 / 상태 | 동작 | 결과·복구 |
|---|---|---|
| 로그인 | 선택한 운영 인증 방식으로 인증 | 로그인 중 재클릭 차단, 실패해도 계정 존재 여부를 과도하게 구분하지 않음 |
| 초대 수락 | 초대 학원·부여 역할 확인 후 수락 | 초대 만료/이미 사용/대상 계정 불일치 구분; 해당 학원 관리자에게 재초대 요청 안내 |
| 학원 카드 | 학원 선택 | 해당 학원의 문서함으로 이동, 이전 선택 학원 작업/문서 캐시 제거 |
| 소속 0개 | 대기 안내 | 가입 신청 또는 초대 요청 경로. 무단으로 임의 학원 공간 생성하지 않음 |
| 소속 여러 개 | 이름·역할로 구별 | 단일 소속일 때 자동 진입 가능; 전역 학원 전환은 계속 제공 |
| 학원 접근 정지 | 비활성 이유 중 공개 가능한 내용 표시 | 문서를 빈 목록으로 위장하지 않음; 다른 소속 학원 전환 허용 |

V1의 계정 생성·비밀번호 재설정·메일 인증은 선택한 인증 방식의 실동작과 함께 구현한다. 작동하지 않는 이메일 발송 버튼을 모형으로 출시하지 않는다. 신규 학원 개설은 소유자 확인이 포함된 운영 절차로 제공하고 결제 상품/청구 UX는 V1 범위에 포함하지 않는다.

## 5. 문서함·작업 목록

- 문서 카드/행: 제목, 학교·학년·학기·시험 종류, 담당자, 마지막 수정, 현재 버전, 처리 상태, 미해결 검토 수, 최신 파일 상태. 학생 손글씨 이름/학번을 제목으로 자동 승격하지 않는다.
- 검색은 제목/학교/시험으로, 필터는 학년·상태·담당자·기간으로 제공한다. 검색 결과 없음과 문서 0개를 다른 문구로 표시한다. 필터 초기화 동작 제공.
- `이어서 작업`: 처리 중이면 작업 상세, 검토 필요면 첫 열린 이슈, 편집 가능하면 마지막 열린 탭, 파일 준비면 내보내기로 연결한다. 서버 최신 상태를 확인한 뒤 이동한다.
- `검토 배정`: owner/admin은 선택 학원 구성원만 고를 수 있다. 교사는 관리자에게 배정을 요청한다. 배정된 문서 목록이 검토자에게 나타난다. 변경 알림은 앱 안에서 제공하고 외부 메일/메신저 알림은 별도 기능으로만 구현한다.
- `복제`: 행 메뉴에서 현재 권한으로 읽을 수 있는 원본의 고정 버전과 새 제목을 확인한 뒤 **같은 학원**에 새 문서·revision 1을 만든다. 원본은 변경하지 않는다. teacher는 원본 `READ`와 해당 학원 `CREATE`가 모두 있어야 하며 reviewer에는 허용하지 않는다. 원본 콘텐츠·출처·템플릿 스냅샷을 복사하되 문서 ACL, final proof, 기존 다운로드 링크는 복사하지 않는다. 새 작성자 권한은 현재 생성 정책으로 부여·기록한다. 완료 시 `복제됨 · 재검증 필요` 표시와 새 문서 열기 링크를 제공하고 기존 최종 상태를 계승하지 않는다.
- 복제 요청 중에는 해당 버튼을 잠그고 같은 요청 ID로 결과를 확인한다. 실패하면 제목·원본 선택을 유지하고 재시도한다. 원본 권한 회수/삭제, 기준 버전 변경, 한도 초과는 원인별로 안내한다. 응답이 불명확하면 새 복제 요청을 만들기 전에 기존 요청 결과를 조회한다. 타 학원 선택·원본에 쓰기·묵시적 파일 복제는 제공하지 않는다.
- `보관`: owner/admin만 실행한다. 운영 문서함에서 숨기고 보관함에서 같은 권한으로 `보관 해제`할 수 있다. 교사·검토자는 요청만 할 수 있다. 보관 해제는 같은 문서를 다시 표시하는 동작이며 과거 콘텐츠 버전 복원과 구별한다. 성공 후 목록 상태와 토스트를 갱신하고, 실패 시 원래 목록 항목을 유지해 재시도한다. 실행 중 작업이 있는 문서는 중단/완료 상태를 먼저 정리한다. 영구 삭제는 별도 owner/admin 권한과 보존 정책을 따르는 파괴적 작업이다.
- 작업 목록: 작업 목적(복원/재검증/파일 생성), 대상 버전, 요청자, 대기/진행/검토 필요/실패/취소/완료. 필터와 해당 문서 이동을 제공한다. 작업 완료가 최종 파일 승인이라는 뜻은 아니다.
- 긴 목록은 페이지 처리 또는 가상 목록을 사용하고 키보드 포커스·필터 복원·권한별 결과를 검사한다. 일괄 삭제/일괄 최종 승인 기능은 V1에 넣지 않는다.

## 6. 새 원본 업로드 및 시험 정보 확인

### 6.1 업로드 순서

`파일 선택 → 서버 업로드/안전 검사 → 페이지 썸네일과 순서 확인 → 시험 정보·학습 범위 확인 → 복원 시작`으로 진행한다. 업로드 자체는 자동 가능하나 인식·풀이 실행은 `복원 시작` 전에는 실행하지 않는다.

| 컨트롤 | 동작 | 성공/실패 처리 |
|---|---|---|
| `사진·PDF 선택` 버튼 / 드롭 | 지원 형식·용량·페이지 수를 사전 안내하고 파일 추가 | 검사 중 진행 표시; 손상·암호 PDF·불지원 형식은 파일별 오류와 제거/교체 |
| 파일별 재시도/제거 | 해당 전송만 재개·제거 | 동일 파일 재선택 허용; 이미 성공한 파일 재전송 불필요 |
| 페이지 카드 | 원래 파일명/원본 페이지·현재 순서/썸네일 표시 | 이름 중복은 허용하고 내부 ID로 분리; 내용 중복 의심은 제안 표시 |
| 순서 이동 | 드래그와 `앞으로/뒤로` 버튼 | 명시 manifest 저장; 파일명으로 재정렬 금지 |
| 순서 추천 | 인쇄 번호/문항 흐름 근거로 변경안 제시 | 자동 적용하지 않고 추천 전후 비교; 사용자 확정 순서를 저장 |
| 회전/잘림 확인 | 비파괴 보기 변환과 수정 미리보기 | 원본은 보존; 인쇄 내용이 잘리면 경고 및 원본 재선택 |
| 페이지 확대 | 인쇄 내용·초점·조명 확인 | 이미지를 못 불러오면 페이지별 재시도, 복원 시작 차단 조건 명시 |
| `복원 시작` | 준비 완료 파일·순서·메타데이터로 요청 | 요청 중 중복 차단; 서버 응답 작업 ID로 진행 화면 이동 |

형식/크기/페이지 한도는 서버 capability 응답으로 표시하고 초과 시 시작 전 차단한다. PDF 지원은 실제 페이지 추출이 검증된 배포에서만 활성화한다. 이미지에서 인쇄 내용이 읽히지 않으면 `더 선명한 원본이 필요합니다`와 문제 영역을 보여주며 추측해서 정상 처리하지 않는다.

시험 정보는 학교, 연도, 학년, 학기, 시험 종류, 과목, 제목, 시험 범위/허용 개념이다. AI 추출값은 `원본에서 추정` 표시로 검토받는다. 수학 V1 외 과목은 지원 범위를 명확히 표시한다. 교육과정·학교 진도가 불명확하면 `학습 범위 확인 필요` 이슈를 만들고 학년 적합 풀이 최종 판정을 통과시키지 않는다.

원본은 외부 AI 처리될 수 있다는 실제 운영 데이터 취급 안내를 `복원 시작` 전에 제공한다. 외부 전송 대상·보관 정책·권한 확인은 채택된 제공자 정책과 일치해야 하며 Gemini는 기본 경로에 없다. 학생 이름·학번이 필요 없는 영역은 출력에서 제외하고 전송 최소화 정책에 맞춰 처리한다. 손글씨라는 이유로 인쇄선까지 지운 미리보기를 원본 대신 숨겨서 사용하지 않는다.

### 6.2 실물 인수 예

심원중 샘플은 `_02 → 기본 → _04 → _03 → _01`이 논리 순서다. 확인 화면은 `대문항 23 / 채점 단위 28 / 총점 100`을 서로 구별한다. `31`은 부모 포함 구조 노드 수이므로 교사에게 `31문제`라고 표시하지 않는다. 이 수치는 샘플 전용이고 다른 시험의 고정 제한이 아니다. 논술형 부모 배점을 자식과 중복 합산하지 않는다. [S03, S07, S11]

## 7. 작업 진행·재시도·중단

단계는 `원본 준비 → 인쇄 내용 복원 → 문항 구조 확인 → 원본 대조 → 정답·풀이 확인 → 결과 저장`으로 교사에게 설명한다. 파일 생성·파일 검사는 별도 작업 단계로 표시한다. 세부 내부 단계가 늘어도 사용자 단계와 진행 근거는 유지한다.

| 상태 | 표시 | 가능한 조작 / 주의 |
|---|---|---|
| 대기 | `처리 순서를 기다리고 있습니다`, 대기 원인 | 문서함 이동·취소. 실제 값 없으면 순번/예상시간 만들지 않음 |
| 진행 | 현재 단계·완료 페이지/전체 페이지 등 측정 가능한 수량 | 완료 단계만 체크. 화면을 닫아도 서버 작업 지속 |
| 사용량 한도 대기 | `학원 사용 한도에 도달했습니다` 또는 `처리 서비스가 잠시 대기 중입니다` | 관리자 안내·재개 가능 시각이 확인되면 표시. 자동 유료 제공자 전환 금지 |
| 연결 일시 끊김 | `상태 연결을 복구하고 있습니다. 작업은 계속될 수 있습니다` | 상태 재조회. 서버 실패로 단정하거나 새 작업 생성 금지 |
| 검토 이관 완료 (`COMPLETED_REVIEW_HANDOFF`) | 작업은 `검토로 이관`, 문서는 `검토 필요`(`NEEDS_REVIEW`); 처리된 문항/남은 이슈 수 | `검토 시작`, 원본 재확인. 작업 진행 중·전체 완료 초록 표시 모두 금지 |
| 실패 | 실패 단계·사용자 원인·추적 번호 | 해당 단계 재시도, 파일 교체, 관리자 문의. 완료 checkpoint 유지 |
| 취소 요청 중 | `안전하게 중단하는 중` | 최종 상태 전 취소 완료 표시 금지; 중복 클릭 차단 |
| 취소됨 | 보존된 원본/완료 단계 범위 | `이어서 처리` 가능 여부를 서버가 결정; 새 버전/작업 연결 기록 |
| 결과 저장 완료 | 문서 버전·검토/편집 링크 | 서버 저장 및 검증 상태 확정 후 완료 공개 |

재접속은 작업 snapshot + 이벤트 커서로 복원한다. 같은 이벤트를 중복 표시하지 않는다. `404`, 인증 만료, 서비스 장애는 재연결 반복으로 숨기지 않는다. 진행 화면 URL에서 문서 연결은 서버 job 정보를 사용한다. 사용자가 입력한 `?doc=`를 신뢰하지 않는다. [A18–A23]

검토 대기는 실행 중 작업의 무한 대기가 아니다. `WAITING_REVIEW`는 단계 이벤트이며 checkpoint·issue·handoff를 저장한 원래 작업은 terminal `COMPLETED_REVIEW_HANDOFF`로 종료한다. worker/학원 동시 실행 슬롯과 lease를 반납하므로 문서함의 `처리 중` 수나 동시 실행 사용량에 포함하지 않는다. 문서 자체는 `검토 필요`를 유지한다.

검토가 끝나면 최신 문서 버전으로 새 후속 검증 작업(successor)을 만들고 `검토 반영됨 · 다시 확인 중`으로 연결한다. 원래 작업을 다시 실행 중으로 바꾸지 않는다. 원래 작업 페이지에도 후속 작업의 진행/성공/실패/취소와 이동 링크를 요약하고, 재차 검토가 필요하면 최신 열린 검토 항목으로 연결한다. 같은 검토 완료를 중복 제출해도 후속 작업을 중복 생성하지 않는다. 오래된 버전의 미시작 후속 작업은 `새 버전 작업으로 대체됨`(`CANCELLED`, 사유 `OBSOLETE_INPUT`)으로 표시하며 오류 재시도로 되살리지 않는다. 이전 버전에서 늦게 끝난 성공 결과를 최신 문서의 검증 완료로 표시하지 않는다.

## 8. 원본·예외·정답 풀이 검토

### 8.1 목록과 원본 비교

검토 헤더는 `확인이 필요한 항목 n개`와 `파일 준비 조건`을 별도로 표시한다. 조회 중 `0개`를 먼저 보여주지 않는다. 미해결 이슈, 확인됨, 보류를 분리하고 유형(누락/문자/수식/보기/도형/풀이/서식), 문항, 원본 페이지로 필터한다.

선택 항목은 `객관식 6 · 도형 · 선분 DC의 길이`처럼 문항 라벨+필드 경로+현재값을 표시한다. 보기 기호와 본문의 ㄱ·ㄴ·ㄷ 목록은 서로 다른 필드다. 수식 index나 JSON 문자열을 교사의 유일한 식별자로 쓰지 않는다.

넓은 화면은 원본/처리본/복원 결과를 나란히, 좁은 화면은 같은 위치를 유지하는 탭으로 제공한다.

- **원본**: 보존된 사진·전체 페이지·선택 영역. 확대/축소·맞춤·회전 보기·이전/다음 페이지.
- **처리본**: 필기 제거 후보와 제거 영역 오버레이. `처리 후보`로 표시하며 원본과 동기 확대/스크롤. 처리본을 완전 정답으로 표시하지 않는다.
- **복원 결과**: 본문·선택지·수식·재작도 도형. 원본과 다른 위치/내용 강조, 출처 없는 요소는 확인 필요.
- **도형 오버레이**: 원본 위 재작도 선/점/라벨·삭제 후보를 개별 토글, 불투명도·맞춤·보기 초기화. 사진 왜곡 때문에 단순 픽셀 중첩이 수학적 동일성을 보증하지 않는다. 정합 변환과 비교 범위를 표시한다.
- 점/선 선택 시 `점 A`, `AB ∥ CD`, `직각`, `같은 길이 표시`, `라벨 8 cm`, 인쇄/필기/미확정 분류를 보여준다. 도형 관계 편집은 원본 복원 판단과 사용자 조건 변경을 구분한다.
- 이미지 전송/조회 실패는 `원본을 확인할 수 없어 확정할 수 없습니다`와 재시도. 근거 없는 확정 버튼 활성화 금지.

### 8.2 검토 행동과 결과

| 행동 | 저장 계약 / 결과 |
|---|---|
| 후보 선택 | 읽기 가능한 텍스트·수식·도형 후보 선택; 원본 근거와 판독 결과 확인 |
| 직접 값 입력 | 필드별 입력기/검증(숫자·보기·배점·수식·관계); 빈 값 허용은 명시 규칙 |
| `원문 확인·반영` | 현재 버전/필드/근거로 canonical 변경 원자 저장 → 새 버전 → 종속 검증 무효화. 성공 뒤에만 해당 이슈를 확인됨으로 이동 |
| 값이 이미 맞음 | 실제 원본 확인한 필드만 검토 기록. 전체 문서/풀이/HWP 검증까지 자동 승인하지 않음 |
| `판독 불가` | 사유·원본 위치 유지, 보류/원본 교체 요청. 정답을 추측해 이슈를 닫지 않음 |
| 누락 문항 | 원본 영역 지정 → 재추출 후보 또는 수동 복원 → 공유 지문/번호/보기 확인 → 저장·재검증 |
| 누락/손상된 도형 | 원본 증거 확인 → 구조 후보 수정/재작도 요청 → 관계·라벨 비교 → 저장·재검증 |
| 논리·정답 충돌 | 해당 본문·조건·선택지·풀이를 연결해서 보기 → 잘못된 부분 수정/재풀이 → 결과 재검증 |
| 오탈자로 보이는 원문 | 복원은 인쇄 원문 유지 + 이슈 기록. 교정을 원하면 `편집본에서 수정`으로 명시 전환 |
| 마지막 이슈 반영 | `원본 검토 완료, 남은 검사 진행 중` 등 실제 gate 표시. 자동 출고 가능 안내 금지 |

확정 요청은 항목별 busy/오류/재시도, 중복 방지, 충돌 비교를 제공한다. 실패 시 입력·후보·스크롤 유지. 성공 시 다음 열린 이슈에 포커스 이동하면서 반영 결과를 재열 수 있다. 일괄 `모두 확인`으로 판독 근거를 생략하는 기능은 V1에서 제공하지 않는다.

### 8.3 정답·풀이·학년 검토

교사용 검토 탭에서 문항별 정답 기호와 실제 값, 풀이 단계, 사용 개념, 해당 학년/범위 판단, 확인 근거를 표시한다. 객관식 계산값·보기 내용·정답 기호가 일치하는지 따로 보여준다. 논술 부모 지문 아래 각 소문항의 답·풀이를 분리해 빠진 자식을 찾을 수 있다.

`풀이 다시 검토`와 `원문 확인`은 별개다. 모델끼리 답이 같아도 독립 검증 여부가 입증되지 않았으면 합의 완료라고 쓰지 않는다. 학생의 체크·손글씨 풀이를 정답 근거로 쓰지 않는다. 검토자는 범위 밖 공식을 확인하거나 대체 풀이를 제안할 수 있고 저장 뒤 풀이 검증을 다시 수행한다.

심원중 회귀 항목: 2③·4③·8④·9①·10⑤·14⑤·20⑤, 16③. 10번/16번 학생 선택은 오답이므로 정답 후보로 자동 채택하지 않는다. 논술2-1은 중2 범위 근거를 보여주고, 13번 표식·20번 해칭의 인쇄/필기 불확실성을 숨기지 않는다. 검토 기준 데이터 자체의 확정도 별도 인수 시험을 거친다. [S01–S04, S06, S10]

## 9. 편집기와 자연어 편집

### 9.1 작업 공간

- 넓은 화면: 문항 목차 / 문서 미리보기 / 편집 패널. 목차 클릭과 미리보기 문항 선택은 동일 안정 ID를 선택한다. 라벨·위치 번호·내부 ID를 혼동하지 않는다.
- 문항 목차는 `객관식`, `논술형 1`, `1-1`, `1-2`의 계층과 공유 지문·도형을 표시한다. 논술형 뒤에 일괄 `번`을 붙여 라벨을 바꾸지 않는다.
- 미리보기는 본문/보기·수식·도형·서술 공간이 실제 콘텐츠와 연결되어야 한다. 상단에 `편집 미리보기 · v12`를 표시한다. 최종 파일 미리보기는 해당 파일 검사 화면과 구별한다.
- 기본 미리보기는 학생 본문이다. `정답·풀이 보기`를 켜면 교사용 상태를 명시한다. 페이지/문항 전환 시 교사용 정보가 학생 출력 설정으로 복사되지 않는다.
- 직접 편집과 자연어 편집은 같은 변경 API·버전·검증 경로를 사용한다. 표면상 텍스트만 바뀌고 구조 데이터가 남는 별도 우회 저장 경로를 만들지 않는다.

### 9.2 자연어 편집의 확정 순서

1. 대상을 선택한다. 칩에 `객관식 6`, `논술형 2의 소문항 전체`처럼 표시하고 선택된 안정 ID를 요청에 포함한다. 자연어가 다른 문항을 지목하면 요청 전에 대상 확인으로 돌린다.
2. 여러 줄 입력란에 요청한다. 예시: `선택한 문항의 답안 공간을 늘려줘`, `선택한 문항의 8 cm를 10 cm로 바꾸고 풀이를 다시 검토해줘`. `숫자만 바꿔줘`처럼 값이 불명확하면 후보 제안·추가 입력을 요구한다.
3. `변경안 만들기`는 저장하지 않는다. 요청한 지시문·기준 버전·대상을 잠근다. 다음 지시 입력은 별도 초안으로 유지한다.
4. 변경안에 문항·필드별 전/후, 영향받는 정답/풀이/도형/레이아웃, 재검증 대상, 적용 불가 사항을 표시한다. 요청 범위를 벗어난 변경은 자동 적용하지 않는다.
5. 교사가 `변경안 적용`을 누르면 전체 선택 변경을 원자적으로 저장한다. 일부 적용이 필요하면 사용자가 명시 선택한 독립 변경들로 새 변경안을 만들어 검증한다. 서버가 임의로 일부를 건너뛴 것을 성공이라고 표시하지 않는다.
6. 새 버전과 `재검증 필요/진행 중`을 표시하고 검증을 예약한다. 문항 조건이 바뀌면 기존 정답·풀이·관련 도형·파일의 최신 유효성을 해제한다. AI 생성 제안은 적용만으로 `사람이 확인함`이 되지 않는다.
7. 검증 실패는 해당 문항으로 연결한다. 완료되면 성공 범위와 버전을 표시하고 `변경 취소`/이력 링크를 제공한다.

V1에서 모든 자연어 콘텐츠 변경은 위 변경안 확인을 거친다. 단순 문서 제목 변경 같은 직접 폼 저장은 작은 저장/되돌리기 동작으로 처리하며 모달을 강제하지 않는다. 원문 복원 작업과 의도적 조건 변경이 같은 작업 로그 이름으로 섞이지 않게 `원문 확인`, `작성자 편집`, `서식 변경`을 구분한다.

`비슷한 문제 생성`, 신규 문제 자동 제작·외부 문제은행 가져오기는 V1.1 비활성 기능이다. 작동하는 예시나 누를 수 있는 주 버튼으로 배치하지 않는다. 요청되면 `현재는 기존 문제의 복원·수정만 지원합니다`와 지원 동작을 안내한다.

### 9.3 수식·도형·레이아웃·답안 공간

| 편집 대상 | V1 조작 범위 / 제한 |
|---|---|
| 수식 | 시각 수식과 구조 편집, 숫자/문자/단위 토큰 확인. 수식 11pt·숫자 it·단위 roman을 출력 계약으로 유지; raw LaTeX를 정상 결과로 보여주지 않음 |
| 도형 | 허용된 점·선·교점·각·원·라벨·평행/직각/등길이 등 구조 도구. 원본 근거 보존, 잘못된 관계/없는 점 참조는 저장 거절. 임의 코드 실행 입력 없음 |
| 도형 배치 | 문항 블록 내 크기·위치 조정. 의미·라벨 가독성·선종류 보존 검사. 못 재작도한 crop 대체는 `초안` 표시 |
| 객관식 레이아웃 | A4 기본, 2열×열당 2문항; 좌상→좌하→우상→우하. 한 페이지 1/2/3/4 문항의 행 짝은 (1,3), (2,4)라는 안내 미리보기 |
| 동일 행 높이 | 각 행의 더 긴 블록 높이에 맞춰 짧은 쪽 여백. 수식 축소/선택지 삭제로 맞추지 않음 |
| 긴 문항·논술형 | 보존해야 할 지문/도형/소문항 묶음과 답안 공간 우선, 후속 행/페이지로 이동. 실제 적용된 예외를 미리보기에서 알림 |
| 답안 공간 | 소문항마다 높이와 원문 줄 유무 표시, 필요 시 의도적 편집으로 높이 조정. 원본이 빈 공간이면 임의 줄을 추가하지 않음 |

화면에서 최종 페이지 수를 확정 표시하려면 동일 버전의 실제 조판 결과가 있어야 한다. 조판 중에는 `배치 계산 중`, 실패 시 원인·해당 문항을 표시한다. 마지막 정상 미리보기는 그 버전과 현재 차이를 명시하며 최신인 것처럼 보여주지 않는다. 기본 A4와 참고 HWP B4의 차이를 숨기지 않는다. 0.5pt 줄맞춤·11pt±0.1pt는 인수 제안값이며 테스트 명세의 최종 설정과 일치시킨다. [S08–S09]

### 9.4 편집 실패·이동

네트워크/HTML 오류/422/권한/취소 모두 요청 상태를 해제하고 지시문·변경안을 보존한다. 요청 A 응답이 요청 B 입력을 지우지 않는다. 응답이 다른 문서/기준 버전이면 적용하지 않는다. 문서 탭을 닫아도 서버 요청은 상태 조회로 재개할 수 있고 `닫기`를 취소와 혼동하지 않는다. 미저장 수동 편집은 이동 전에 저장/변경 버리기/계속 편집을 선택한다. 저장된 변경안만 있는 경우 이동을 막지 않는다. [A16, A20, A26–A28]

## 10. 변경 이력·비교·되돌리기

- 행: 버전, 작성/검토자, 시각, 행동 유형, 대상 문항, 수정 이유, 관련 요청 ID, 검증 상태. 새로고침·다른 기기에서도 유지된다.
- 버전 2개 선택 → 문항/본문/보기/수식/도형/풀이/배치/브랜드의 변화 표시. 원본 근거와 당시 파일을 조회할 수 있으나 과거 파일을 최신으로 표시하지 않는다.
- `이 버전의 내용으로 복원`은 현재 내용과 비교 후 **새 버전**을 만든다. 과거 기록 삭제·버전 감소·예전 검증 증거의 무조건 재사용은 금지한다.
- 최근 변경 취소도 동일 계약이다. 이후 타인 변경이 있으면 취소 영향 비교 후 처리하고 타인의 편집을 조용히 덮지 않는다. 복원 후 필요한 검증과 파일 재생성을 다시 한다.
- `다시 적용`(redo)은 취소한 변경과 현재 버전의 충돌을 확인한 뒤 새 버전으로 적용한다. 단순히 메모리 내 undo 스택을 되감지 않는다. 의존 대상이 바뀌었으면 자동 재적용 대신 변경안 재작성을 제공한다.
- 제거된 문항도 이력에 원래 ID·출처를 유지한다. 읽기 권한 없는 문서의 로그·이전 버전·파일로 우회하지 못하게 한다.

## 11. 브랜드·학원 설정·사용량

### 11.1 간단 브랜드/템플릿

owner/admin은 학원명·안전한 로고 파일·머리말/꼬리말·페이지 번호·허용 글꼴·기본 템플릿을 관리한다. 미리보기에서 본문 영역 침범, 작은 글자, 잘림, 지원하지 않는 글꼴을 확인한다. 로고 파일 제한·검증은 업로드와 동일한 보안 계약을 사용한다. 사용자 HTML/스크립트/임의 SVG 실행으로 브랜드를 주입하지 않는다.

템플릿 버전 저장 후 `새 문서의 기본값`으로 사용한다. 이미 만든 문서/파일은 자동 변경하지 않는다. 기존 문서에 적용하려면 대상 문서에서 `브랜드 적용 변경안`을 확인하고 새 버전/조판 재검사를 수행한다. 단순 스타일 변경이 의미 검증을 무조건 재풀이하게 만들지는 않되 실제 레이아웃·파일 검사는 다시 한다.

V1 템플릿은 원본 인쇄 라벨, 수식 11pt, 미주, 답안 공간, 2열 줄맞춤을 지키는 제한된 설정이다. 드래그 자유 편집 템플릿 빌더·마켓플레이스·다과목 템플릿은 포함하지 않는다.

### 11.1A 기존 HWP 안전 리브랜딩

`기존 한글 파일에 우리 학원 브랜드 적용`은 파일 분석→대상 확인→브랜드 preview→파일 검사 4단계다. 상단 제목 후보를 머리말·바탕쪽·본문 상단별 page crop으로 보여 주고 복잡한 표+그림 타이틀은 사용자가 block 단위로 확정한다. 워터마크는 모든 페이지 기본이며 농도·크기만 제한적으로 조절한다. 쪽번호 제거 결과와 유지되는 footer를 나란히 보여 준다.

원본은 항상 별도 다운로드 가능하고 mutation하지 않는다. 구조가 불확실하거나 한컴 재열기/허용 영역 밖 visual diff가 실패하면 최종 파일을 제공하지 않는다. 상세 control·proof 계약은 `HWP_REBRANDING_SPEC.md`를 따른다.

### 11.2 구성원·설정

구성원 목록은 역할·상태·초대 만료·배정 문서 링크를 표시한다. 역할 변경/내보내기 권한 회수는 적용 시점과 대상자를 분명히 하고 이력에 남긴다. 마지막 owner 제거는 금지하고 소유권 이전은 명시적 확인을 거친다. 구성원 탈퇴/삭제 시 문서 소유·실행 작업·검토 배정의 이전 대상을 정한다.

사용량은 학원 관리자에게 실제 집계 기간·남은 문서/페이지/처리량 한도·대기 작업을 보여준다. 임의 토큰 비용이나 Codex 계정 잔량을 학원 사용량으로 표시하지 않는다. 교사는 작업 시작 가능 여부·대기 사유만 이해하면 된다. 실제 정책에 없는 자동 과금·자동 상향 버튼은 제공하지 않는다.

### 11.3 플랫폼 운영 화면

운영자는 AI 처리 가용성, 큐·실패/재시도 수, 학원별 사용 한도, HWP 작업자 상태·검사 실패를 본다. 중앙 서비스 오류는 교사 화면에 `현재 HWP 파일을 준비할 수 없습니다`로 번역한다. 교사에게 `Windows + 한컴 설치 필요` 툴팁이나 로컬 설치 지시를 보여주지 않는다. provider/HWP 서비스 설정·자격증명은 서버 운영 통제로 분리한다. 운영 인증 방식이 승인되지 않았거나 서비스가 준비되지 않았으면 교사 작업을 성공시킨 것으로 위장하지 않는다.

## 12. 내보내기·파일 검사·최종 다운로드

### 12.1 용도와 내용 노출

출력 화면 첫 단계에서 버전·템플릿·용도를 선택한다. 저장되는 용도는 파일에 고정하고 다운로드 링크와 파일명에 함께 표시한다.

| 용도 | 내용 | 누출 방지 계약 |
|---|---|---|
| 학생용 문제지 (`STUDENT_ONLY`) | 문제·보기·도형·답안 공간만 | 정답/풀이/미주 본문·숨김 텍스트·댓글·필드·첨부 미리보기 등에서 답이 포함되지 않음 |
| 정답·해설지 (`ANSWER_ONLY`) | 모든 채점 단위의 원래 문항 라벨·참조·정답·풀이 | 문제 본문은 템플릿 정책에 따라 의도적으로 생략하며 출력 manifest에 기록. 다른 버전 문제의 답 연결 금지, V1에는 풀이 제외 옵션 없음 |
| 교사용 해설지 (`TEACHER`) | 문항별 정답+풀이·필요 원문 참조 | 학생용으로 표시하거나 학생용 파일명 사용 금지 |
| 문제+정답·풀이 미주 통합본 (`STUDENT_WITH_ENDNOTES`) | 문제와 실제 미주에 정답+풀이 | 사용자 원요구를 충족하는 기본 제작 결과. `정답 포함` 배지를 화면·파일명에 표시, 정답 없는 학생용으로 부르지 않음 |

원요구인 정답+풀이 미주는 통합본에서 반드시 실제 미주 객체로 구현한다. 학원 기본 출력은 통합본으로 설정할 수 있으나 `학생용`을 선택하면 답을 실제로 제외한 별도 파일을 만든다. 학생용에도 몰래 미주를 넣는 방식은 금지한다. 정답을 화면에서 숨기는 것만으로 파일 누출 방지가 되지 않는다.

미주 정책은 템플릿에 고정한다. V1 기본 `MAJOR_GROUPED`는 심원중의 경우 대문항별 23미주에 논술 자식 풀이를 포함하는 방식이며, 28채점 단위 연결 coverage를 검증한다. 다른 시험은 해당 구조에 맞춰 계산한다. `LEAF` 28개 미주 대안은 템플릿 명시 설정일 때만 허용하고 같은 파일에서 혼용하지 않는다. UI에서는 enum 대신 `대문항별 미주 / 채점 문항별 미주`로 표시한다.

### 12.2 생성에서 검사까지

`내용 확인 → 파일 준비 → 파일 검사 → 해당 형식 최종 다운로드` 순서다. 검사에 필요한 내부 파일 생성은 최종 승인 전에 허용한다. 화면 버튼은 `검사용 파일 준비` 또는 `파일 준비 및 검사`로 명명하고, 완료 전 다운로드 성공으로 표시하지 않는다.

| 형식 카드 상태 | 화면 행동 |
|---|---|
| 확인 전/지원 여부 조회 중 | 최종 버튼 비활성. 상태 조회 오류 재시도 |
| 내용 검증 실패/미수행 | 막힌 항목과 해당 검토 링크. 최종 다운로드 불가; 권한 있는 내부 초안만 별도 생성 가능 |
| 준비 가능 | 지원되는 HWPX/HWP/PDF와 동일 버전·용도·템플릿을 확인하고 생성 요청 |
| 생성/검사 진행 | 현재 단계·작업 이동·중단. 다른 형식 상태는 독립 유지 |
| 검사 실패 | 차이 위치·검사 종류·복구 경로. `검사 통과하지 못함`; 파일 최종 제공 차단 |
| 검사 서비스 불가 | `현재 이 형식은 검사할 수 없습니다`; 미수행을 0건/정상으로 바꾸지 않음 |
| 검사 통과 | 파일명·버전·용도·형식·검사 시각·파일 크기·다운로드 |
| 이후 문서 수정 | `이전 버전 파일` + 최신 버전 생성. 기존 불변 파일을 덮어쓰지 않음 |

필수 검사는 `미수행 / 검사 중 / 통과 / 실패 / 수행 불가`로 표시한다. 누락된 검사값을 통과로 색칠하지 않는다. 내용·수식·도형·미주·학년·레이아웃·파일 재열기 검사의 해당 범위가 동일 버전이어야 한다. HWP 서비스 장애는 HWP 최종 제공을 막지만 독립 검사를 통과한 HWPX/PDF를 자동 실패시키지 않는다. 반대로 PDF 하나가 통과했다고 HWP도 통과 배지로 묶지 않는다.

모든 최종 요청/다운로드는 서버가 현재 권한, 해당 파일의 불변 버전·용도·검사 증거를 다시 검증한다. 버튼 비활성만으로 차단하지 않는다. 링크 만료 시 권한 재확인 후 같은 파일에 대한 새 링크를 발급하며 다른 파일로 대체하지 않는다.

### 12.3 파일 검사 상세 페이지

파일별 상단: 제목, 해당 문서 버전, 생성 시각, 용도, 형식, 템플릿 버전, 최종/초안 여부. 본문에는 실제 생성 파일의 렌더 페이지와 검사 목록을 표시한다. 편집기의 웹 HTML을 최종 파일의 이미지인 것처럼 사용하지 않는다.

차이 항목 선택 → 해당 페이지/문항/수식/도형/미주 영역으로 이동 → 기대값과 실제값 → 원본 또는 편집 화면으로 복구. 잘림·누락·번호 오류·원시 수식 문자열·크기·baseline·정답 유출을 다른 종류로 구분한다. 실패 파일은 `검사용 초안` 표시 없이 정상 다운로드로 노출하지 않는다.

초안은 화면·파일명·문서 표식으로 식별하고 `학생 배포용이 아님`을 명확히 한다. 초안이 손글씨 정답/개인정보가 담긴 원본 crop을 포함할 수 있으면 권한과 내용 노출을 별도 확인한다. 최신본 최종 파일과 초안 파일은 같은 다운로드 슬롯을 공유하지 않는다. [A04–A10, A35, S05–S12]

## 13. 팝업·서랍·토스트 명세

팝업은 필요한 판단에만 사용한다. 루틴 성공·저장에는 상태 영역/토스트, 원본 확대는 비교 창, 복잡한 여러 문항 편집은 전용 패널을 사용한다. OS 파일 선택창은 브라우저 기본 동작이다.

| UI | 열리는 조건 / 내용 | 닫기·저장·실패 정책 |
|---|---|---|
| 원본 확대 비교 dialog | crop/페이지 확대; 원본·처리본·결과·위치 연동 | 읽기 전용은 Escape/배경/닫기 모두 허용, 닫으면 실행 버튼에 포커스 복귀 |
| 페이지 순서 추천 dialog | 자동 추천 후 현재/제안 순서 및 근거 | `순서 적용`만 저장; Escape/배경 취소, 기존 순서 유지 |
| 자연어 변경안 패널 | 요청 완료 후 필드별 diff·영향·검증 범위 | 패널 닫기=제안 유지. `적용`만 저장; 긴/다중 변경은 전체 화면으로 확장 |
| 버전 충돌 dialog | 오래된 기준 버전으로 저장/적용 | `최신본 보기 / 변경안 다시 만들기 / 취소`; 덮어쓰기 주 버튼 금지 |
| 미저장 편집 이동 dialog | 실제 로컬 미저장 변경을 두고 이동 | `저장 후 이동 / 버리고 이동 / 계속 편집`; 기본 초점은 계속 편집, 저장 실패면 머묾 |
| 버전 복원 dialog | 과거 버전으로 복원 | 현재 대비 변경·새 버전 생성·재검증 안내; `새 버전으로 복원`만 실행 |
| 작업 취소 dialog | 진행 중 작업을 중단 | 보존 범위·다시 실행 가능성 안내; `계속 처리 / 중단 요청`, 서버 확인 후 취소 상태 |
| 복제 설정 popover/dialog | 같은 학원·원본 버전·새 제목·재검증 필요 안내 | `복제 만들기`만 생성; 실행 전 Escape/닫기로 취소. 실행 중 닫아도 서버 요청은 별도 상태 조회, 오류 시 제목 보존 |
| 보관/보관 해제 | owner/admin의 가역적 문서 보관 | 토스트+되돌리기, 불필요한 경고 모달 생략; 되돌리기도 현재 권한 재검사 |
| 영구 삭제/소유권 이전 dialog | owner의 파괴적 변경 | 대상 이름·영향·보존 정책 명시, 명시적 확인; 진행 중 중복 금지, 실패해도 창·입력 유지 |
| 구성원 역할 변경 | 접근 범위가 바뀌는 관리 동작 | 현재/변경 역할·대상 표시; 요청 실패 복구, 마지막 owner 제거 차단 |
| 완료/오류 토스트 | 저장/요청 완료 또는 비차단 오류 | 필수 오류·검토 정보는 페이지에도 남김; 토스트만으로 중요한 결과 전달 금지 |

모달 공통: 제목·설명·접근 가능한 이름, focus trap, 첫 초점과 닫힌 후 원위치 복귀, 본문 스크롤 잠금, 스크린리더 배경 비활성, 눈에 보이는 닫기 버튼. 중첩 모달 대신 기존 창 내용 전환/패널 사용. 로딩 중 닫기는 저장을 취소한다는 뜻이 아니며 적용 요청 후에는 서버 결과를 문서 상태에 반영한다. 요청 중 무조건 닫기 불가로 사용자를 가두지 않는다.

작업을 파괴하는 dialog는 배경 클릭으로 확정/실행하지 않는다. Escape는 실행 전 취소로 처리하고 실행 후에는 결과 확인/창 닫기와 작업 취소를 구분한다. 모바일 높이는 실제 가용 화면 이내이며 내부 내용만 스크롤, 고정 하단 버튼은 키보드에 가려지지 않는다. 장문 diff·수식·이미지가 있을 때 확대해도 버튼·설명이 접근 가능해야 한다.

## 14. 반응형·키보드·접근성

- 제안 breakpoint: 1024px 이상에서 3패널(최소 읽기 폭을 충족할 때), 768–1023px에서 목차 서랍+주 화면/보조 패널, 767px 이하는 `문항 / 미리보기 / 수정` 탭. 정확한 breakpoint보다 360/390/768/1280px 사용 가능성이 합격 기준이다.
- 페이지 전체 가로 넘침을 허용하지 않는다. 수식/큰 도형 자체의 의도적 확대 캔버스는 컨테이너 안에서 이동할 수 있으며 `맞춤`을 제공한다. 390px에서 목차·미리보기가 수십 px로 줄어드는 레이아웃 금지.
- 모바일 업로드·페이지 순서·확대·검토·다운로드는 완결 가능해야 한다. 복잡한 도형 편집도 전용 전체 화면과 점/관계 목록으로 접근하게 하며 단순히 PC 사용 안내로 기능을 숨겨 합격 처리하지 않는다.
- Tab 순서, 보이는 포커스, 실제 button·label, 오류 연계, 선택한 문항 접근 가능한 이름. 상태는 색뿐 아니라 문자·아이콘으로 구분한다.
- Enter는 단일 값 확정에만 명시 사용한다. 자연어 textarea Enter는 줄바꿈, 제출은 버튼 또는 안내된 Ctrl/Cmd+Enter. 모든 제출은 IME `isComposing`/조합 상태를 확인한다. Escape는 정해진 닫기 정책을 따른다.
- 수식 시각 렌더에 읽기 가능한 수식 대체 설명, 도형에 점/관계 목록, 이미지 원본에 페이지·영역 이름. 화면 읽기 도구가 요청 진행을 매 이벤트마다 반복 낭독하지 않도록 핵심 상태만 공지한다.
- V1은 일관된 light 테마를 기본 제공한다. 다크 테마가 미구현이면 OS 다크에 따라 텍스트만 밝게 바꾸지 않는다. 다크를 출시할 때 모든 surface/text/폼/상태/preview의 대비를 함께 검사한다.
- 200% 브라우저 확대, 긴 학교명·문항 라벨·오류문, 큰 글씨, 좁은 화면·가상 키보드에서 버튼 잘림을 검사한다. 키보드만으로 로그인→업로드→검토→변경안 적용→파일 다운로드가 가능해야 한다. [A29–A32, 프런트 감사 F20]

## 15. 화면별 완료 증거와 금지 문구

| 화면 | 필수 완료 증거 |
|---|---|
| 로그인/학원 전환 | 역할별 진입, 초대 만료, 타 학원 URL/캐시/파일 접근 차단 |
| 업로드 | 중복 파일명·역순 사진·다중 PDF·실패 후 같은 파일 재시도, 순서 저장 |
| 진행 | 실패 단계 표시, query 없는 링크, 새로고침/재연결, 대기/취소/복구 |
| 검토 | 한 필드 확정이 실제 canonical·preview·새 버전에 반영, 빈 문서/0카드 출고 차단 |
| 편집 | 안정 ID 대상, 변경안 확인, 실패 입력 보존, 원자 적용, 관련 풀이/파일 무효화 |
| 도형/서식 | 원본/처리본/재작도 대조, 손글씨 배제, 11pt/줄맞춤/소문항 공간 확인 |
| 이력 | 새로고침 후 유지, 복원이 새 버전 생성, 타인 변경 충돌 처리 |
| 브랜드 | 학원 간 분리, 템플릿 버전 변경이 과거 파일을 바꾸지 않음 |
| 출력 | 동일 버전 HWPX/HWP/PDF 각각 증거, 실제 파일 미리보기, 학생용 답 누출 검사 |
| 공통 | 360/390/768/1280px·IME·키보드·오류·권한 회수·다중 탭 검증 |

화면에서 사용하지 말 것: `전체 검수는 필요 없습니다`, 근거 없는 `100% 정확`, 모든 파일을 묶은 무조건 `VERIFIED FINAL`, 검사가 없는 `오류 0개`, 개인 구독으로 다학원 서비스 무제한 사용 안내. 대신 `확인이 필요한 항목`, `이 파일에서 수행한 검사`, `확인된 버전`, `검사하지 못한 항목`을 구체적으로 표시한다.
